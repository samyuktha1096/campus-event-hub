# Campus Event Hub

A responsive campus event listing and registration website. Students can discover activities, create accounts, register/cancel registrations, and publish events. Administrators can view counts and delete events.

## Problem and objectives
College event information is often scattered across noticeboards and chat groups. This project centralizes event discovery, event publishing and seat registration, with persistent data in PostgreSQL.

## Roles and features
- **Student:** browse/search/filter events, create events, register and cancel registrations.
- **Admin:** student features plus summary counts and event deletion.
- The account whose email matches `ADMIN_EMAIL` in `backend/.env` receives the admin role at signup. Configure this before creating the admin account.
- Password hashing (bcrypt), 12-hour JWTs, API rate limiting, server-side validation, database constraints, atomic capacity checking.

## Stack
HTML5, CSS3, Vanilla JavaScript, Node.js 20+, Express, Supabase PostgreSQL. Packages: `@supabase/supabase-js`, `bcryptjs`, `dotenv`, `express`, `express-rate-limit`, `helmet`, `jsonwebtoken`.

## Prerequisites
Install [VS Code](https://code.visualstudio.com/), [Node.js LTS](https://nodejs.org/) (20+), [Git](https://git-scm.com/downloads), and create a free [Supabase](https://supabase.com/) project. Verify in VS Code terminal: `node --version`, `npm --version`, `git --version`.

## Setup
1. Create a Supabase project. In project settings/API, copy the project URL and server-side service-role key. The service-role key is secret and must never be placed in frontend files or GitHub.
2. Open Supabase **SQL Editor**, paste all of `database/schema.sql`, and run it. In Table Editor, verify `users`, `events`, and `registrations` exist.
3. Edit `backend/.env`:
```env
PORT=3000
NODE_ENV=development
SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SUPABASE_SERVICE_ROLE_KEY
JWT_SECRET=REPLACE_WITH_A_LONG_RANDOM_SECRET
ADMIN_EMAIL=you@example.com
```
Generate a secret from the project root: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`. Paste output into `JWT_SECRET`; use your own credentials, not the placeholders. `.env.example` is a safe template and is included in Git; `.env` is ignored.
4. In terminal from the project root run:
```powershell
cd backend
npm install
npm run check
npm start
```
Expected server output: `Campus Event Hub running at http://localhost:3000`. Open http://localhost:3000. Health check: http://localhost:3000/api/health returns `{"status":"ok","app":"Campus Event Hub"}`. Stop with Ctrl+C; `npm run dev` runs in watch mode.
5. Create the admin account using the configured `ADMIN_EMAIL`, then create a student account and publish a future event. Register for it and test cancellation.

## Architecture and security
Browser fetch requests go to Express. Express validates payloads, verifies JWTs and checks roles. A server-only Supabase client accesses PostgreSQL. RLS is enabled with no public policies; the privileged service-role key bypasses RLS and is only used by Express, so route authorization is important. Passwords are bcrypt hashes, and JWTs expire in 12 hours. The demo stores JWTs in localStorage, which is suitable for a learning project but less secure than HttpOnly cookies for production.

## REST API
All responses are JSON. Protected endpoints use `Authorization: Bearer <token>`.
| Method | Path | Purpose/access |
|---|---|---|
| GET | `/api/health` | Health check; public |
| POST | `/api/auth/signup` | Create account (`name,email,password`); public/rate-limited |
| POST | `/api/auth/login` | Login (`email,password`); public/rate-limited |
| GET | `/api/auth/me` | Current account; logged in |
| GET | `/api/events` | Published event list, counts, registration status; public |
| POST | `/api/events` | Create event (`title,description,category,venue,starts_at,capacity`); logged in |
| GET | `/api/events/me/registrations` | Current user's registrations; logged in |
| POST | `/api/events/:id/register` | Register; logged in; duplicate/full prevented |
| DELETE | `/api/events/:id/register` | Cancel own registration; logged in |
| GET | `/api/admin/summary` | Aggregate counts; admin |
| DELETE | `/api/admin/events/:id` | Delete event and registrations; admin |

Typical errors: 400 invalid input, 401 missing/invalid token, 403 wrong role, 404 missing item, 409 duplicate/full registration, 500 server/database error. Server logs retain details; client receives a generic 500 message.

## Testing checklist
- `/api/health` returns status `ok`.
- Valid signup/login works; duplicate email and wrong password are rejected.
- Invalid/past event dates and invalid capacities are rejected.
- Search and category/date filters update the list.
- A future event can be created and registered for; registration count updates.
- Duplicate registration is rejected; cancellation frees a seat.
- With capacity 1, the second attendee receives a full-event error.
- Admin summary without a token returns 401; student token returns 403.
- Admin deletion removes the event and registrations.
- Check layout at desktop and mobile widths.

## Troubleshooting
- Missing env error: verify names and restart the server.
- Supabase API/database errors: ensure URL and service-role key are from the same project and schema SQL ran successfully.
- JWT secret error: use a random value of at least 32 characters.
- Port busy: change `PORT=3001` and visit localhost:3001.
- npm not found: reinstall Node.js LTS and reopen terminal.
- Admin button missing: ensure `ADMIN_EMAIL` matched the email at signup. Existing accounts are not auto-promoted; update the trusted user's role in Supabase Table Editor.
- Do not open `index.html` directly; start Express and use localhost.

## Limitations
No email verification, password reset, event editing, notifications or attendee export. Organizers can create events; only admins can delete them. The remote Supabase connection cannot be verified until you configure your own credentials.

